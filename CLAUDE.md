# Project policy

Browser tower defense game, built with Vite and TypeScript. The game board is rendered in 3D with Three.js; menus and icons are plain DOM and Canvas 2D. It has no UI framework.

## Verify

- `npm run typecheck` must pass.
- `npm run build` must pass. It also produces `dist/artifact.html`.
- `npm run build:pages` builds the GitHub Pages version (base `/tower-defense/`, service worker `dist/sw.js` from `scripts/sw.js`, manifest and icons from `public/`). Run it when touching `vite.config.ts`, `src/pwa.ts`, `public/` or `scripts/sw.js`.
- `npm run balance` plays whole runs with the bots in `src/game/bots.ts` and prints a table per map (`--map`, `--strategy`, `--runs`, `--weapon`, `--charm`, `--waves`, `--seed`, `--boons random|greedy`, `--squad auto|each|<four ids>`, `--mills none,early,greedy,late,safe|all`, `--json`; it also prints combos per run and boon pick rates). Run it after changing numbers in `src/data/`; the mixed bot should win every story map with lives to spare, and single-tower bots should do clearly worse. The lab's Balance tab runs the same bots in the browser.
- For gameplay changes, run `npm run dev` and drive a run from the console. In dev, `window.__dw` exposes `startRun`, `currentGame`, `update`, `startWave`, `spawnEnemy`, `placeTower`, `canBuild`, `chooseBranch` and the rest of `game/run`, `game/towers` and `game/hero`, and `window.__view` is the `GameView`. For close-ups call `__view.setFocus({ x, y, halfWidth })` (simulation pixels, half width in tiles); moving the camera directly does not stick. Other modules can be reached with `await import('/src/game/boons.ts')` and the like. Step `update(game, 1/60)` in a loop to simulate whole runs quickly; a run stops at a boon choice until one is taken (keys 1-3 work from the console via a dispatched `keydown`). Tower types are `spark`, `frost`, `pulse`, `star` and `kite` (the Skyhook). Changing the hash during a run opens the pause menu instead of navigating; to jump to another screen, load the page again with the new hash. Map ids are `mill`, `marsh`, `ford`, `bramble`, `fork` and `ring`. To test locked pages or the squad, edit `duskwatch-save-v1:<id>` in localStorage and reload (importing `/src/save.ts` from the console can give a separate module copy), and put the player's save back afterwards. With the Browser pane hidden, screenshots can lag a frame behind; take two. Towers are placed by position in simulation pixels, for example `placeTower(game, 'spark', 3.5 * 60, 2.5 * 60)`.
- The dev server sometimes keeps serving a stale `src/main.ts`; dev handles added elsewhere (as `__view` in `play.ts`) load reliably.

## Conventions

- The game is in English first. Every player-facing string goes in `src/i18n/en.ts`, with a Swedish counterpart in `sv.ts`. Never hard-code display text in game or UI code.
- `src/data/` holds plain numbers with no display text.
- The simulation in `src/game/` must not touch the DOM, so it can be stepped headless for balance tests. The simulation never imports from `src/three/`.
- Tower placement is free, not on a grid: a tower may stand anywhere on the board that is `ROAD_CLEARANCE` from the road centreline and `TOWER_SPACING` from other towers (`canBuild` in `game/towers.ts`). The user asked for this so players can use the space cleverly. Do not reintroduce a visible grid.
- UI colors come from the tokens in `src/style.css`; 3D colors come from `C` in `src/three/models.ts`.
- All 3D models are built in code from primitives in `src/three/models.ts`, which must stay free of DOM access so `npm run export-models` can run it in Node. The user chose code-built models over ArtCraft's AI generation and the Codex ArtCraft MCP prototype.
- `src/three/view.ts` maps simulation pixels to world units (one tile = one unit, board centred on the origin) and keeps one 3D object per tower, enemy and shot in sync each frame. It detects events by watching state: a tower fired when its cooldown jumps up, an enemy was hit when `lastHit` changes, and an enemy that disappears with `hp <= 0` was killed (otherwise it leaked).
- Towers have no shared plinth; the user rejected the grey plate. Each tower is built in stages that show its level in its shape: levels 1-3 are three different buildings of the same kind (for the Spark: a stake, a lamp post, a watch booth), each branch at level 4 is a form of its own, and levels 5 and 6 add detail to it. Each tower stands on its own blotchy ground patch (`patch`), which has no outline so it reads as ground.
- Every tower carries a visible weapon that the shot visibly leaves from: shooters have an aimed head with a `muzzle` (Spark's lantern spout or barrel, Rime's ice lance, Starfall's telescope), and the view starts each shot at the muzzle and blends it onto the simulated path. Area towers have spouts around them, each holding a `jet` that the view blasts outward on every pulse. The user asked for this; a lone flame or crystal that just emits a wave did not read as a weapon.
- Models expose named parts that the view animates: towers use `muzzle`, `jet`, `pitch`, `aim`, `recoil`, `swing`, `core`, `flames`, `embers`, `float`, `orbit`, `mist`, `spin`, `arc`, `flag`, `badge`; enemies use `body`, `skin`, `footL/R`, `wingL/R`, `armL/R`, `cloak`, `shield`, `buds`, `sack`, `core`, `jaw`, `slow`, `burn`, `stun`; each Warden weapon in `makeHero` has a `muzzle` the Warden's shots leave from. Keep these names when reworking a model.
- `npm run export-models` writes every model to `exports/models/*.glb` (gitignored) so the user can view them in ArtCraft via 3D Stage > Upload 3D Model.
- `GAME_TITLE` in `src/config.ts` is a working title until the project gets a real name.

## Art direction ("storybook golden hour")

- Cel-shaded with outlines: `toon()` gives three hard light steps, and `addOutlines` in the view adds an inverted-hull outline to every opaque toon mesh. New models should use `toon()` for surfaces, `gem()` for faintly self-lit ice and magic, and `glow()` only for true light sources.
- Golden hour, not night: a low warm sun with long shadows, a cool sky fill, a pink rim light and a gradient sky. The user rejected a dark theme and ground light pools around towers. Keep glow modest so only light sources bloom, and avoid bright additive flashes and screen shake on routine hits, which made the board blink.
- Two sides in color: the village is warm brass, wood and cool stone; the Gloom is violet and magenta ink with yellow-green eyes, and it stains the grass purple around its rift.
- Everything moves: towers pop in when built, idle (swinging lanterns, floating crystals, living flames) and react when they fire (recoil, flare). Enemies spawn with a pop, waddle, flap or stomp by type, flash white when hit, and squash and burst when killed. Heavy impacts (a star landing, the Shooting Star, a Gloom Lord falling) hold the picture for a few frames in the view only; there is no screen shake (the simulation still sets `g.shake`, but nothing reads it). Sounds are all synthesised in `src/audio.ts`, softened by one compressor and a minimum gap per voice. Faces sit high on the front so they read from the near top-down camera.
- The look is soft, not blocky: one smooth terrain mesh with the road painted in along a rounded curve, a rounded island, and smooth shading by default.
- Camera: fixed, orthographic, tilted `CAMERA_TILT` from straight down so models show a little of their sides. `fitCamera` frames the whole playable board for any window shape, and the island has `MARGIN` tiles of scenery so the rest of the screen is land, never sky. The player cannot turn or zoom; the user asked for a fixed view.

## Game screen

- The board fills the whole window (`#game` is fixed full-screen). Controls live on the board as storybook props instead of a toolbar: a resource plaque top left, round buttons top right (speed, pause, sound, menu), a build belt of tower medallions bottom centre, a wave horn anchored just below the road's entrance, and a tower card that opens beside the selected tower. World-anchored pieces are positioned each frame in `placeAnchors` (`ui/play.ts`) via `GameView.screenOf`.
- Belt medallions and tower cards show real 3D portraits rendered once by `towerPortraits()` in `three/view.ts`; `branchPortrait()` (level 4 of each branch) and `enemyPortraits()` are cached the same way.
- Tower controls (the block at the end of `ui/play.ts`): hovering a tower shows the quick "+" (or two branch buttons) with its price, and hovering those shows a note with only the changed stats while `view.setRangeFocus` eases the ring to the next range. A 0.7 s hover or a click opens the card. On touch: tap shows the quick buttons, a long press opens the card, a branch takes two taps, and building takes a tap to place the ghost and a second tap on it to build. Phones held upright get a "turn sideways" note that pauses the run. Check control changes with a mouse and at about 812x375.
- Under the wave horn, the next-wave preview shows a portrait per coming shadow with its count and trait icons; `towerAttrIcons()` in `ui/traits.ts` gives a tower's attribute row (hits flyers or not, trait bonuses) for the belt tip and the card.
- First-run hints (`ui/hints.ts`) show one bubble at a time (build, call the wave, upgrade, place the Warden), each waiting for the action and stored per profile in `save.hints`. The bubble sits above its target, or below when there is no room.
- The end of a run is `ui/endrun.ts`, with results and unlocks computed in `meta.ts`. The menu button opens a pause menu (Resume, Settings, How to play, Give up), and the browser's back button during a run opens it too.
- The whole UI shares one storybook style in `src/style.css` (parchment `--parch`, ink `--ink-d`, brass `--brass`, stardust `--dust`), with chunky ink outlines and drop shadows to match the cel-shaded board. There is no dark theme any more.
- The board is always on screen. Behind the front door, `startAttract()` in `ui/play.ts` runs a silent, endless demo on Mill Hill with one of each tower; `mode` in `play.ts` keeps input and the HUD off during the demo. Map pictures are real stills from `mapPortrait()`, cached in `three/view.ts`.
- Short screens (phones held sideways) get a `max-height: 500px` block in the front-door CSS; check new front-door views at about 812x375 as well as desktop.

## Screens

- All screens share the one board, switched through `nav` (`ui/nav.ts`, wired in `main.ts`) and addressed by hash: `#` title, `#play` mode choice, `#story` and `#story/<map>` the storybook, `#survival`, `#lodge`, `#lodge/talents`, `#lodge/workshop`, `#lodge/squad` (once the squad unlocks), and `#lab`. The browser's back button works throughout. `#play` and `#survival` lead to the storybook until Survival opens (watch level 3, when the first four towers are unlocked; later towers do not hold it back); unknown addresses lead to the title.
- The front door (`ui/front.ts`) is the title (profile chip, settings gear, one big Play, the Lodge), the mode choice, the storybook (one spread per story map with the shadows it sends and, once unlocked, the squad strip from `ui/squad.ts`; unreached pages are pencil sketches with no words or button) and the survival list. Play starts Mill Hill at once on a first visit.
- Overlays live in `ui/settings.ts` and share one `#sheet`: settings (volume, language, shortcuts, profile rename, switch, new, reset, version), the profile list, How to play and the shortcuts list (`?` in game). The sheet box gets the class `sheet-<name>`; do not reuse a sheet name as a content class.
- Profiles (`save.ts`): each profile has its own save key `duskwatch-save-v1:<id>`, with the list and active profile in `duskwatch-profiles-v1`. Switching, creating and resetting replace the contents of the exported `save` object but keep the same object, so modules may hold on to it. The volume is stored per device in `audio.ts`, not per profile.
- `ui/play.ts` owns the board and runs in one of three modes: `menu` (silent demo), `play` (a run, including the sandbox) and `gallery` (the lab's line-up). Other screens drive it through `startRun`, `startAttract`, `adopt` and `setFrameHook`.

## Combos, boons and bosses

- Combos (`game/combos.ts`, one row per combo in `COMBOS`): Shatter (Starfall on a chilled or frozen shadow), Steam (Ember Pulse on a chilled shadow bursts onto its neighbours) and Conduct (Spark on a stunned shadow). Only chills and stuns made by towers count, and the Warden never sets one off. The view draws the combo word over the shadow (`drawComboWords`), at most a few at once. A new combo needs a `ComboId`, a `COMBOS` row and strings.
- Boons (`data/boons.ts`, `game/boons.ts`, cards and plaque icons in `ui/boons.ts`, the boon block in `ui/play.ts`): after every fifth cleared wave (not the last) the run offers three; the next wave waits until one is taken. Boons change stats through `Tower.mods` / `Hero.mods` and hooks marked `// boons between waves`. Cards are picked by tap, click or keys 1-3, ignore presses in their first 0.45 s, and fold into a pill with "Look at the board first". Taken boons show as a second row in the plaque. The menu demo never offers boons.
- Bosses (`game/bosses.ts`, numbers on the `boss` field in `data/enemies.ts`, banner and bars in `ui/boss.ts`): each story map sends its own boss last in its boss waves (`maps.ts`): the Thief on Mill Hill steals gold and runs back, the Stomper on Marsh Ditch knocks out nearby towers (`Tower.knocked`), the Mender on Ring Rampart heals non-boss shadows while not burning. Willow Ford sends the Thief, Bramble Wood the Stomper and the Forked Road the Mender. Bosses take half the slow and cannot be frozen. Health bars sit top centre on wide screens and under the corner buttons below 1300 px.

## Squad, terrain, rifts and mills

- Towers: Spark, Rime, Ember Pulse and Starfall, plus the Skyhook (`kite`, watch level 5): a harpoon ballista with kites on `orbit` that does double damage to flyers. Kite Flock throws three harpoons (one `muzzle` each) and cannot hit the ground; Whaler throws one heavy harpoon with a bonus against armour.
- The squad (`game/squad.ts`, `ui/squad.ts`): once a fifth tower is unlocked, each run brings four towers, stored per profile in `save.squad` and chosen in the Lodge's Squad tab or on the storybook page. The belt and keys 1-4 follow the squad; towers left at home cannot be built and get no boons. The lab's "all towers" switch shows every tower. Bots bring a squad too.
- Terrain (`game/terrain.ts`, round patches in `terrain` on a map in `data/maps.ts`): hills give 25% more reach to a tower or the Warden on them; woods and water cannot be built on; woods block straight shots (Spark, Rime, Skyhook, the Warden) but not Starfall shells or pulses; water slows walking shadows to 60% and Thunder Pulse deals 60% more to shadows in it. The placement ghost says which rule applies.
- Rifts that move: a map may list extra roads in `rifts` and the order in `riftOrder`; each wave walks its rift's road (`g.paths[g.rift]`), split shadows stay on their parent's road, and placement checks every road. The wave horn and next-wave preview move to the next rift and say which side it opens on; `placeAnchors` lifts them clear of the build belt for a rift at the bottom edge.
- Story maps in order: Mill Hill, Marsh Ditch, Willow Ford (river and hills), Bramble Wood (woods), The Forked Road (three rifts); Ring Rampart is Survival.
- Mills (`data/mills.ts`, `game/mills.ts`, `ui/mills.ts`) are a lab-only economy experiment behind `g.dev.mills` (the sandbox's "Mills (experiment)" switch, key M). They are not in the player's game; the user has not decided whether to keep them. Board clicks for mills are caught by window listeners in `ui/mills.ts` before `play.ts`.

## The developer lab (`ui/lab.ts`)

- A tool for the user while developing, opened at `#lab` (there is no link in the game). Keep it working whenever towers, enemies or the Warden change.
- Gallery: every tower, every enemy and the Warden lined up on Ring Rampart, with buttons for level, branch, firing, hits, kills, statuses, the Warden's loadout and ability, a wave-strength slider and stat tables, plus a Combos section (one button per combo) and Stomp, Grab gold and Mend buttons for the bosses lined up on the inner loop. Animations are triggered by nudging state (`cd`, `lastHit`, `castAt`), which the view picks up even while paused. "Live combat" unpauses with invulnerable, pinned dummies.
- Sandbox: a normal run with `game.dev` switches (god mode, infinite gold, all towers), spawn buttons (bosses included), an "Offer boons now" button, fractional speed and frame stepping. A dev run never ends and never pays stardust.
- Balance: runs the bots from `game/bots.ts` in 40 ms slices, with chips for maps, bots, run count and the Warden's weapon. Bots switch off the player's meta upgrades and ignore watch level, so results do not depend on the save.

## The Warden (the player's hero)

- One per run, placed for free from the first belt medallion (hotkey H), levelled with gold (`heroUpgradeCost`), never sold. Logic in `game/hero.ts`, data in `data/hero.ts`, model `makeHero` in `three/models.ts`.
- The user wants a customisable hero: everyone starts with the same kit and unlocks clothes, looks and abilities over time. The loadout is the build: the weapon decides the attack and the ability the player casts (Q or the ability seal), the charm adds a passive, and hat and cloak are looks only. Items and talents are bought with stardust in the Warden's Lodge (`ui/lodge.ts`) and stored in `save.hero`.
- Balance (tuned with `npm run balance`): the default staff Warden deals about 15–17% of the damage with the mixed bot. The sling still takes about twice as many kills as damage, because it always shoots the shadow nearest the heart (targeting in `game/hero.ts`).

## Planning

- Order agreed with the user: make the core loop fun first (game feel, meaningful decisions, balance). Then add breadth (maps, towers, the build-your-own-road mode). Head-to-head comes last: local same-screen first, then against AI, then online.
- Levelling happens both inside a run and between runs. Inside a run, towers level up only when the player pays gold. There is no automatic XP; the user explicitly rejected it. The branch choice at level 3 is itself the paid upgrade to level 4. Between runs, the player has a watch level and stardust upgrades.
- Gameplay ideas the user wants, planned in `docs/plans/gameplay.md`: a balance tool in the lab, game feel, enemies with traits that demand the right tower plus a next-wave preview, combos between towers, a pick of one of three boons between waves, bosses with their own mechanics, terrain that matters, a rift that moves on advanced maps, and the storybook campaign. Economy buildings only if they play well. Towers carry attributes (can hit flyers, bonus against shadow traits) so new shadow types plug in as data; the set of tower types stays small, and once a fifth tower is unlocked the player picks a squad of four per run, and the best squad should differ between story maps. Saved for later: a daily challenge with a leaderboard.
- Shadow traits are data: the trait list (`flying | armoured | mends | splits | sprints`) is in `src/types.ts`, each shadow in `data/enemies.ts` lists its traits and tuning, and tower attributes (hits flyers, bonuses per trait, overrides per branch) are in `data/towers.ts`. A new trait needs an entry there plus an icon in `ui/traits.ts`. Trait bonuses apply before armour; armour always lets a quarter through, and burning ignores it. Each map has its own written wave list in `data/maps.ts`; Ring Rampart repeats its list with 35% more shadows each round. The names Inkblot, Droplet and Scurrier are placeholders until the user confirms them.
- Ideas the user rejected; do not propose them again: dusk as a mechanic and anything built on darkness (including shadows that snuff lanterns), weather, an active ability per tower (too busy), veteran badges on towers, a bestiary.
- In-game UI the user chose: hovering a built tower shows a small "+" button that upgrades it in place. When a branch is due, it shows two buttons instead, and hovering one shows what that branch does. A longer hover or a click on the tower opens the full card with all values, as today. The card previews what the next upgrade gives (for example "9 → 12" and a growing range ring). A settings panel holds volumes, language and the keyboard shortcuts. Skipped for now: belt hover info, red invalid-placement feedback, moving the card off the road, undoing a sale, gold and life feedback, retiring the tip banner, a richer end screen.
- Every view shows exactly what that moment needs and nothing more. The plan for the start of the game (title, story, survival, settings, profiles) is in `docs/plans/front-door.md`. The game will be published on GitHub Pages as an installable web app for friends and family to test on their phones; see `docs/plans/release.md`. Every new UI must therefore work with touch, not only hover and keys.

## Publishing

- The public repository is github.com/sockulags/tower-defense. Every push to `main` runs `.github/workflows/pages.yml`, which runs `npm run build:pages` and deploys to https://sockulags.github.io/tower-defense/ as an installable web app.
- The Pages build alone registers the service worker (`src/pwa.ts`), which caches every built file for offline play and shows an update note when a new deploy is waiting. `APP_VERSION` comes from `package.json`; bump it for releases.
- Fonts are self-hosted woff2 files in `src/fonts/` (OFL); do not add Google Fonts links. App icons in `public/icons/` are rendered from the real heart model by `npm run icons` (needs local Chrome or Edge).
- The game is also published as a private claude.ai Artifact at https://claude.ai/artifact/LjdboXzVdcQvxs4tFVmkTL. To update it, publish `dist/artifact.html` (from `npm run build`) with that URL.
